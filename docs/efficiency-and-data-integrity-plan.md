Its role mix must remain unrestricted. Keep its existing route live until the shared path passes the data and score gates below; a mid-season cutover must not change historical standings or interrupt trades.

## Original-league cutover, during this season

1. **Establish the gate.** The live read-only parity check on 2026-09-29 found 44 cast assignments and all nine rates matched, and zero week/team score differences across 88 legacy snapshots, two completed weeks, and four teams. Rerun `node scripts/check-default-league-parity.mjs` before each stage. Extend it to compare the real shared snapshots once populated, rather than adapting legacy rows in memory.
2. **Represent the one intentional rules difference.** The shared workspace now bypasses roster-balance prompts and proposed claim/trade caps for the original league, matching the database's existing default-league exceptions. Keep newer leagues' Pro/Star/Bonus limits. An explicit `enforce_role_balance` league setting would remove hard-coded identity checks, but is not a prerequisite to this cutover and should not be added without updating all database checks together. Do not change `roster_size` or introduce per-role limits for the original league.
3. **Shadow the original snapshots.** The owner applied `supabase/shadow-default-league-snapshots.sql`. The 2026-09-29 private SQL check verified 88 legacy and 88 shared snapshots with zero field mismatches (including team, role, rate, and `created_at`); assignments and current rates also had zero mismatches. The public weekly score comparison still reports zero differences. An authenticated run of `node scripts/check-default-league-parity.mjs` would additionally score the real shared rows, but the exact-row comparison already verifies that the adapted rows are identical.
4. **Migrate trade state safely.** The owner applied `supabase/shadow-default-league-trade-history.sql`. The 2026-09-29 private SQL check verified all three historical events in both tables with zero field mismatches; there were zero open offers, unread legacy results, and unmappable events. Open offers may appear later and would need a separate atomic handoff at cutover; do not mirror a pending offer while both trade systems can act on it. Temporarily stop new trade writes during the brief switch, reconcile again, then use only the shared trade RPCs. Never silently drop an open offer or notification.
5. **Shared workspace active; observe before retiring legacy code.** The owner applied both `supabase/enable-default-shared-claims.sql` and `supabase/prepare-default-shared-trades.sql` on 2026-09-29. The claim bridge calls the authorized legacy swap and retains the `cast_members.fantasy_team_id` → `league_roster_assignments` mirror; accepted shared trades update both roster representations in one transaction. Before activation, the private check showed both bridges installed, zero open offers, 88 matching snapshots, and three matching trade events. On 2026-09-29 the route flag was set to true in an atomic transaction guarded by empty legacy/shared offer tables. A separate read-only SQL check confirmed true. The signed-in original league loaded the shared Home, My Team, Dances, and League views without the preview banner; the four teams, current roster, rates, and historical standings appeared. Score Desk and Cast Roster remain on their existing owner surfaces. Keep the reversible flag and legacy tables through at least one week-completion and trade cycle; rollback restores the old read path but does not erase completed shared trades or their history.
6. **Retire after observation.** Once a full week completion and trade cycle succeed, remove original-only RPCs, tables, and scoring code in a separate migration. Keep a database backup and measured totals. Decide season scoping before the next cast enters (F18); this is separate from the current cutover.

The public API cannot read private trade or shared-snapshot tables anonymously, so those gates require an authenticated owner session or read-only SQL in the Supabase editor. No live route switch should be inferred from the current zero-mismatch public check alone.

Do not split `app.js` (F8), add a session module (F19), move all rules/scoring to SQL (F10/F2B), or delete broad CSS groups (F20) merely for architectural tidiness during this live season. Those changes become smaller or unnecessary after the original path is retired.
